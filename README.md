# gomisat

A CDCL SAT solver and exact model counter in Go, with two ways of stating the
problems they answer: reliability models of coherent systems, and finite-domain
constraint problems.

It began as a port of MiniSat 2.2 and was taken through the pieces a counting engine
needs. Competing on pure SAT performance was never a goal.

**Goal: exploit systematic structural similarity across reliability WMC queries.**

Reliability evaluation does not ask one counting question, it asks a sequence of
them, each differing from the last by a change generated by a known rule: a
threshold, a `k`-out-of-`n` bound, a configuration, a mission phase. The aim was to
reuse the decomposition and the component cache across such a sequence.

That aim has been measured, and the answer was not the expected one. The reuse needs
no special machinery and is worth a steady factor of about four; what decides the
cost is the branching order and the choice of encoding.
[DESIGN.md](DESIGN.md) records every phase, every measurement, and the several
predictions that turned out wrong along the way.

## Status

The solver decides SAT/UNSAT, reports a model, solves under assumptions and reports
an UNSAT core, and can be reused across queries. All 2185 SATLIB instances in
`testdata/satlib` are answered correctly, and **1223 of the 1234 instances of the
larger corpus are decided within 10 s each**, in 599 s in total. The eleven that are
not are the ten `par32` instances and `hole10`, none of which CaDiCaL decides in 60 s
either: every instance of the corpus that an independent modern solver decides, this
one decides too.

Counting is exact and weighted. With a component's probability on its "works"
literal, the weighted count of a structure function is the reliability of the system.

```console
$ make build
$ ./bin/gomisat -count testdata/satlib/sat-uniform-20-91/uf20-01.cnf
c decisions 32 conflicts 12 components 16
c cache hits 0 misses 16 entries 16
s mc 8
```

```go
m := reliability.New()
pumps := m.Events("pump", 3)
for _, p := range pumps {
    m.SetProbability(p, 0.95)
}
m.Assert(m.AtLeast(2, pumps...))   // two of the three must work
fmt.Println(m.Reliability())       // 0.992750
```

```go
c := csp.New()
x, y := c.IntVarRange(0, 10), c.IntVarRange(0, 10)
c.Add(csp.LeZero(csp.NewSum(map[*csp.IntVar]int{x: 2, y: 3}, -12))) // 2x + 3y <= 12
c.Add(csp.GeZero(csp.NewSum(map[*csp.IntVar]int{x: 1, y: -1}, 0)))  // x >= y

sol, _ := c.Solve()      // sol.Int(x), sol.Int(y)
count, _ := c.Count()    // 13
```

## Layout

```
pkg/gomisat/     the solver and the model counter
pkg/reliability/ structure functions of coherent systems, encoded to CNF
pkg/csp/         finite-domain constraint problems: order encoding, solving, counting
cmd/gomisat/     solve or count one file
cmd/gomibench/   sweep a corpus, check answers, compare against a baseline
cmd/gomiencode/  compare encodings of one model by what they cost to count
testdata/satlib/ committed instances, expected answer encoded in the names
corpus/          manifest and known answers of the larger corpus
bench/           recorded measurements
docs/            the user and developer guides
```

## Development

```console
$ make check         # go vet and the regression suite
$ make test-full     # the same over all 2185 committed instances
$ make corpus        # fetch the larger corpus (about 99 MB, once)
$ make corpus-compare # re-run it and compare against the recorded results
```

Go 1.24 or later, no dependencies outside the standard library. Regenerating
`corpus/expected.tsv` needs `python-sat`, and is rarely necessary.
